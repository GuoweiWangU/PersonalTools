# 长期主控与多模型执行架构

## 1. 目标

把当前一次性飞书 Worker 调用升级为可持续完成复杂任务的主控系统。主控负责理解目标、制定计划、分派任务、检查结果和调整后续步骤；云端执行系统负责持久化、长时 Session、资源调度、异步执行、故障恢复和结果通知。

典型任务包括环境部署、数据准备、模型训练、实验评估、结果分析和多轮修正，而不是仅执行单条命令。

## 2. 当前基础与未实现边界

已验证：

- 飞书群消息、结构化 JSON 任务和自然语言 `/glm`、`/kimi`、`/mock` 命令。
- 单机 Bridge、多 Worker 路由、白名单群与发送者、事件及任务幂等。
- Kimi Code ACP 独立短会话、GLM OpenAI 兼容调用。
- systemd 用户服务与异常自动重启。

尚未实现：

- 通用命令与文件执行、持久 Task／Session、长任务队列、跨任务依赖、审批、资源锁和主控规划。
- 当前 Kimi ACP Worker 仍是只读短任务模式，不能据此宣称已经可以部署或训练。
- 当前飞书用户身份发送授权尚未完成，Mac 主控主动向群分派仍待验证。

## 3. 总体分层

```text
用户
  ↓ 飞书群／当前 Kimi Work 对话
交互层：命令解析、飞书线程、通知、审批
  ↓
主控层：目标理解、计划、DAG、Worker 选择、结果验收、重规划
  ↓
控制层：Task／Session／Turn、调度、资源锁、审批、恢复、审计
  ↓
执行层：Kimi ACP、GLM、SSH、数据、训练、评估等 Worker
  ↓
状态与产物：SQLite、日志、Artifact Manifest、对象或文件存储
```

飞书只是交互与传输层，不是事实来源。主控可以暂时离线；已经批准的云端任务仍按持久计划执行。Mac 主控在线后继续读取控制层状态并接管分析和分派。

## 4. 核心对象

### Goal

用户的高层目标，例如“完成一次小规模训练并给出评估报告”。Goal 保存验收标准、约束、优先级和最终产物，不直接等同于某一次模型调用。

### Plan 与 Step

主控把 Goal 拆成有依赖关系的 Step。每个 Step 包含：

- 输入引用、预期输出和验收标准。
- Worker 类型、工作目录、资源需求和超时。
- 前置 Step、失败策略、重试上限和审批要求。

计划执行前保存版本；后续重规划不覆盖历史版本。

### Task

Task 是可持续多轮执行的业务单元，绑定固定 Worker、工作目录、权限和一个长时 ACP Session。环境部署、数据准备、训练和评估可以属于同一 Goal 的不同 Task，也可以按用户意图在同一 Task 中连续推进。

### Session

Session 保存长时模型上下文。`task_id ↔ session_id` 持久化到 SQLite。每轮可以新建 ACP 进程，但必须通过 `session/load` 或 `session/resume` 恢复原 Session，不得隐式创建新上下文。

只有明确新建 Task、关闭后重建或 Session 无法恢复时才更换 Session。Session 恢复失败要进入 `blocked` 并报告，不能静默清空上下文。

### Turn

Turn 是 Task 中的一次指令执行，保存指令、开始与结束时间、ACP 停止原因、结果、错误、日志和产物。Task 与 Turn 状态分离，避免一次 Turn 成功就把长期 Task 标记为完成。

### Artifact

产物通过 Manifest 引用，不直接塞进飞书或模型上下文。Manifest 至少包含路径、类型、大小、哈希、生成 Task／Turn 和校验结果。大型日志、数据集和模型文件只传受控引用与摘要。

## 5. 状态机

Goal／Task 状态：

```text
draft → awaiting_approval → queued → running
running → waiting_input | waiting_approval | succeeded | blocked | failed | cancelled
blocked → queued（阻塞解除后）
failed → queued（满足重试条件且副作用可安全恢复）
```

Turn 状态：

```text
queued → running → succeeded | blocked | failed | cancelled
```

所有状态变化带时间、原因和操作者，形成审计历史。服务重启后先恢复状态，再决定哪些任务可继续，不能把 `running` 一律重置为失败。

## 6. 主控职责

主控不是简单转发消息，必须执行控制闭环：

1. 澄清目标和验收标准，识别缺失输入。
2. 制定 Step DAG，选择合适 Worker 和资源。
3. 检查计划、权限与副作用，必要时请求批准。
4. 调度执行并读取状态、日志和产物。
5. 独立验证结果，不能只相信 Worker 的自然语言总结。
6. 失败时定位是环境、数据、资源、权限还是模型问题，再重规划。
7. 汇总最终产物、未知项和可复现信息。

主控自身有长期控制 Session；Worker Session 相互隔离。跨 Task 信息通过计划、结构化结果和 Artifact Manifest 传递，不直接共享全部对话上下文。

## 7. Worker 模型

- `mock`：确定性链路测试。
- `glm`：无状态文本分析、独立复核或结构化处理。
- `kimi`：Kimi 只读分析，保持现有安全边界。
- `agent`：Kimi 通用执行，支持文件和命令，绑定持久 Session。
- 后续专用 Worker：SSH 连通性、数据校验、训练启动、评估和产物检查。

通用 Agent 负责复杂操作，专用 Worker 负责可确定、易验证的动作。能用确定性程序完成的检查不依赖模型自由生成命令。

## 8. 长任务与调度

长任务必须异步执行，Bridge 不能等待训练结束后才处理下一条消息。

调度器需要：

- 每 Task 串行 Turn，防止同一 Session 并发写入。
- Goal 内按 DAG 依赖调度，不同 Task 可并行。
- GPU、机器、目录和资源锁，防止重复训练或数据写入冲突。
- 有界队列、超时、心跳、取消和优雅停止。
- 副作用幂等键；启动训练前检查已有运行和产物，避免重复扣费或占用 GPU。
- 分段日志与进度摘要，定期写入 SQLite。

训练、评估等外部进程需要独立 run_id、PID／作业 ID、机器、工作目录和检查点引用。Bridge 重启后通过这些信息对账，而不是盲目重启任务。

## 9. 权限与安全

默认采用受控通用执行：

- 仅白名单群和发送者可创建或控制任务。
- 文件写入限制在授权项目和数据目录，路径规范化后检查，阻止目录穿越。
- SSH 仅允许白名单主机，凭证由本机 Agent 或密钥管理器提供。
- Secret 不进入飞书、SQLite、日志、模型 prompt 或 Git。
- 高风险删除、系统级修改、对外发布、资金相关操作需要单独审批。
- 权限按 Task 授予，不因一个 Task 获得权限而扩散到其他 Task。
- 所有审批、命令、文件变更和外部副作用保留审计记录。

“自动批准”只能作用于策略明确允许的范围，不能简单对所有 ACP permission request 选择 allow。

## 10. 故障恢复

- SQLite 事务保证 Task、Turn 和 Session 映射一致。
- 服务启动时执行恢复扫描：运行中 Turn、外部进程、心跳和产物逐一核对。
- ACP 进程退出不等于 Session 丢失；从持久 session_id 恢复。
- 外部训练仍在运行时只重新接管监控，不重复启动。
- 不可恢复任务进入 `blocked` 或 `failed`，说明原因和下一步，不伪造成功。
- 重试只用于可重入步骤；有副作用步骤必须先检查现状。

## 11. 验收与结果

每个 Step 需要机器可检查的验收条件，例如：

- 环境：命令退出码、依赖版本、GPU 可见性。
- 数据：Manifest、样本数、划分约束、校验和。
- 训练：进程状态、指标文件、检查点、资源使用。
- 评估：固定配置、样本数、结果文件和统计口径。
- 文档：引用真实产物，不编造路径、指标或完成状态。

主控最终回复必须区分已验证事实、模型总结、未知项和阻塞问题。

## 12. 飞书交互

建议命令：

```text
/goal 目标内容               创建复杂目标并由主控规划
/agent 任务内容              创建通用 Task 与持久 Session
/continue TASK-xxx 指令      继续同一 Task 和 Session
/tasks                       查看任务列表
/status TASK-xxx             查看状态、阶段和产物摘要
/logs TASK-xxx               查看最近受控日志
/approve TASK-xxx            批准待审批步骤
/deny TASK-xxx 原因          拒绝并记录原因
/cancel TASK-xxx             取消执行
/close TASK-xxx              关闭长期 Task
```

飞书回复线程可绑定 task_id，线程内后续消息默认继续同一 Task；显式命令优先级更高。长任务完成、阻塞或等待审批时主动通知。

## 13. 实施阶段

### 阶段 A：可靠基础

- 修复 GLM JSON 解析与真实错误展示。
- 实现 Task／Session／Turn SQLite 模型和 ACP Session 恢复。
- 开放受控通用执行，先验证短任务和权限策略。
- 完成 Mac 用户身份向群分派的授权与验证。

### 阶段 B：长任务执行

- 异步队列、取消、日志、心跳、资源锁和恢复扫描。
- SSH 白名单、训练与评估外部进程对账。
- `/status`、`/logs`、`/cancel` 等管理命令。

### 阶段 C：主控闭环

- Goal、Plan、Step DAG、Worker 选择、独立验收和重规划。
- 审批、通知、飞书线程绑定和 Artifact Manifest。
- Mac 主控离线期间的云端持久执行与在线后接管。

### 阶段 D：硬化

- 故障注入、重复事件、服务重启、Session 损坏和训练中断测试。
- 权限绕过、路径穿越、Secret 泄漏和资源争用测试。
- 小范围真实任务验证后再扩大自动化范围。

## 14. 首个端到端基准

首个复杂基准应是可控且可恢复的小任务：

1. 主控创建 Goal 和计划。
2. 通用 Agent 检查指定机器环境。
3. 在授权目录准备小型测试数据。
4. 启动一个分钟级、无重要副作用的训练或计算任务。
5. 运行固定评估并生成结构化产物。
6. 主控独立检查产物，再向飞书汇报。
7. 中途模拟 Bridge 重启，验证 Task、Session 和外部运行能够恢复。

该基准通过后，再扩展到真实环境部署、长时间训练和多机协作。
